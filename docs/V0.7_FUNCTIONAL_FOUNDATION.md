# Medqur V0.7 Functional Foundation

V0.7 prioritises working clinical infrastructure over visual redesign.

## Implemented in V0.7

### Medication identification

- Camera accepts QR, DataMatrix, Code 128, Code 39, EAN-13, UPC-A and UPC-E in medication mode.
- `MedicationIdentifierParser` recognises GS1 identifiers and extracts the common healthcare fields when present:
  - AI (01): GTIN
  - AI (10): lot/batch
  - AI (17): expiry date
  - AI (21): serial number
- Supports parenthesised GS1 text and common compact/FNC1 sequences.
- EAN/UPC identifiers are normalised to GTIN-14 for comparison.
- Existing manufacturer identifiers are preferred. Medqur does not require a second proprietary QR on a medicine that already carries a usable standard identifier.
- Unknown GTINs are never guessed. They are marked as requiring medication-master/pharmacist verification.

### Prototype medication master

`MedicationMasterCatalog` is the boundary for an eventual Jamaica-wide approved product master. The public repository contains only explicitly marked demo products; it does not invent mappings between real GTINs and medicines.

A production catalogue should be populated from approved Ministry, regulatory, procurement or pharmacy master-data sources.

### Closed-loop medication administration

The patient record now performs a scan-based safety sequence:

1. scan patient wristband;
2. confirm the encounter;
3. scan the medicine;
4. parse the product identifier;
5. compare the scanned GTIN/code with the package mapped to the signed order;
6. block expired products when a machine-readable expiry is present;
7. block repeat administration of an already-completed order;
8. perform a conservative exact medication/allergy conflict check;
9. show missing lot/expiry/master-data information as warnings;
10. record the administration only after confirmation.

This remains prototype logic and is not a substitute for an approved medication formulary, interaction engine, pharmacy verification or clinical policy.

### NIC / NIDS scanning boundary

The camera can physically capture QR payloads from the back of an NIC/NIDS card. `NidsIdentityDecoder` separates three cases:

- Medqur test credential: may autofill the prototype because Medqur generated and understands it.
- Structured but unverified credential: captured but not trusted.
- Opaque NIC credential: captured but not trusted.

Unverified NIC QR contents are fingerprinted with SHA-256 for safe correlation without displaying or logging the full raw value.

The repository intentionally does not invent the private/official NIRA QR schema. Real NIC autofill requires an approved NIRA verification gateway, authentication material, consent/authorisation rules and an official response profile. `NiraVerificationGateway` is the integration seam for that service.

### Security foundation

- `MedqurSecurity.generateOpaqueToken()` creates cryptographically strong random opaque IDs for future staff/patient credentials.
- `SecureEnvelopeCodec` implements AES-256-GCM envelope encryption when a legitimate 256-bit key is supplied by secure key management.
- No encryption key is hard-coded into the Flutter application.
- SHA-256 fingerprints are used for sensitive scanned identifiers in audit metadata instead of raw NIN/QR values.
- `StaffCredential` models a revocable opaque staff credential rather than embedding licences, passwords, biometrics or permissions inside a QR.

Production key storage must use platform/server key management. AES code alone does not make a public client secure if its key is embedded in the app.

### Audit foundation

`AuditEvent`, `AuditPrivacy`, and `AuditSink` define an append-only audit boundary. A production sink should be server-side and integrity protected. Important events to emit include identity scans, triage changes, wristband prints/reprints, medication orders, barcode mismatches, blocked administrations, successful administrations, credential issuance/revocation and record access.

### FHIR-shaped integration

The integration adapter now exposes prototype-shaped resources for:

- Patient
- Encounter
- Observation (vitals)
- AllergyIntolerance
- MedicationRequest
- MedicationAdministration

These are integration boundaries, not a claim of conformance with a Jamaica/e-Care implementation guide.

## Real NIC/NIDS support: what is still required

The current camera/scanner can read a physical QR. What Medqur cannot safely do without NIRA documentation/access is decide that arbitrary text inside a QR is an authenticated Jamaican identity.

To finish real NIC support:

1. obtain the official NIRA third-party verification technical specification;
2. obtain approved credentials/certificates and test environment;
3. determine whether the physical QR is an opaque identifier, signed credential, URL/token or another format;
4. validate signatures/certificates if the card itself contains a verifiable credential;
5. otherwise send the opaque credential to NIRA over mutually authenticated TLS/API authentication;
6. request only the minimum necessary attributes;
7. verify response freshness and status;
8. map the verified identity to an existing Medqur patient or create a new patient;
9. never silently merge uncertain patient matches;
10. audit the verification without storing raw QR payloads unnecessarily.

## Next implementation stages

### V0.8 — Identity and workforce

- NIRA sandbox/production adapter once official access exists.
- Credential-management admin module.
- Revocation/reissue of staff QR credentials.
- Expanded roles: triage nurse, nurse, doctor, pharmacist, registration clerk, laboratory, radiology, facility admin and system admin.
- Device/passkey enrolment and backend session tokens.
- Professional registration verification adapters for doctors/nurses when authoritative interfaces are available.

### V0.9 — Medication and pharmacy

- Approved Jamaica medication product master.
- Pharmacy receiving and stock by GTIN/lot/expiry.
- Dispense workflow and pharmacist verification.
- Unit-dose DataMatrix/label generation only where manufacturer/unit packaging lacks a usable code.
- Recall search by GTIN + lot.
- Medication order scheduling and due-time validation.
- Structured allergy/interaction/formulary checking using approved clinical data sources.

### V0.10 — Clinical operations

- Dedicated triage nurse workspace with editable/repeated vitals.
- Real-time doctor/nurse/pharmacy work queues.
- Laboratory specimen barcode generation and collection verification.
- Radiology orders/worklists.
- Blood-product verification workflow.
- Emergency unknown-patient merge/reconciliation controls.

### V0.11 — Infrastructure

- Authenticated backend and PostgreSQL clinical persistence.
- Realtime sync with conflict handling.
- Offline event queue for network outages.
- Server-side append-only audit ledger.
- FHIR server/API profile validation.
- Ministry/e-Care adapter once an approved interface is available.
- Medqur Print Bridge and later Zebra ZD510-HC direct printing.

## Safety boundary

The public Medqur repository remains a prototype. Real NIDS, real patient data, production medication administration, government credentials and Ministry/e-Care access must not be enabled until the relevant authoritative interfaces, security controls, clinical governance and approvals are in place.
