# Medqur V0.13 responsive UX contract

Medqur follows a **less-is-more clinical UI**. Responsive behavior is not a cosmetic afterthought: the same workflow must stay readable, touch-safe and calm from a small phone to a desktop browser without horizontal overflow, broken labels or walls of helper text.

## Layout targets

The regression matrix uses these representative viewport widths:

- 320 px — very small phone / worst-case narrow layout
- 360 px — compact phone
- 390 px — modern iPhone-class width
- 768 px — tablet / narrow desktop window
- 1024 px — tablet landscape / laptop window
- 1440 px — desktop browser

Shared breakpoints live in `lib/widgets/medqur_responsive.dart`. Screens should consume those primitives instead of inventing one-off width checks.

## Rules

1. **No horizontal screen overflow.** Forms stack before a field, menu, status chip or button becomes cramped.
2. **Content has a maximum readable width.** Desktop layouts gain whitespace and grids; they do not stretch forms edge-to-edge across a monitor.
3. **Secondary copy is short.** Normal screens use one or two lines of helper copy. Longer standards, policy and prototype explanations belong in Help/About, expandable detail or a dedicated information screen.
4. **Critical clinical data remains visible.** Patient identity, allergies, acuity, medication, dose, route, timing and hard-stop safety messages are never removed merely to make a screen look cleaner.
5. **Responsive cards and grids.** Dashboard summaries use adaptive columns; small phones fall back to fewer columns instead of shrinking labels until they break.
6. **Touch targets stay usable.** Primary controls remain approximately 44–48 px high even when visual density is restrained.
7. **Text may wrap only where useful.** Titles and safety information can wrap deliberately; secondary labels use max-lines/ellipsis so a single verbose string cannot destroy the layout.
8. **Desktop navigation changes shape.** Large screens use a navigation rail and wider workspace; phones/tablets use bottom navigation.
9. **Modal surfaces are bounded.** Desktop dialogs/sheets should not become full-monitor-width panels. Phone sheets may use the available width.
10. **Progressive disclosure over instruction walls.** Show the action first; expose detail when the clinician asks for it.

## Shared primitives

- `MedqurResponsive` — breakpoints and adaptive page padding
- `ResponsiveFields` — horizontal form controls that stack when cramped
- `ResponsiveActions` — action buttons that become full-width rows on narrow screens
- `ResponsiveGrid` — adaptive dashboard/card grid
- `CompactHelperText` — capped secondary helper copy
- `MedqurPage` / `MedqurPageHeader` — centered readable content and overflow-safe heading behavior
- `SoftCard`, `SectionTitle`, `StatusPill` — compact, overflow-safe common UI

## Validation rule

Every major screen change should keep the responsive widget tests green. New high-traffic screens should be added to the viewport matrix when practical. A successful desktop layout is not proof that the phone layout works, and vice versa.

This responsive/less-is-more contract is a standing Medqur product rule for future UI work, not a one-release preference.
